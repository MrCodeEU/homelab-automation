# Keycloak SSO & SonarQube Setup Guide

This document provides step-by-step instructions to complete the Keycloak SSO and SonarQube integration.

## Architecture Overview

```
                     Internet
                         |
                     Caddy (mljr:443)
                         |
         +---------------+---------------+
         |               |               |
    auth.mljr.eu    logs.mljr.eu    sonarqube.mljr.eu
         |               |               |
    Keycloak         forward_auth     forward_auth
    (mljr:9732)          |               |
         +----------oauth2-proxy---------+
                     (mljr:4180)
```

**How it works:**
1. User visits a protected service (e.g., logs.mljr.eu)
2. Caddy's `forward_auth` sends request to oauth2-proxy
3. oauth2-proxy checks if user has valid session cookie
4. If not authenticated, redirects to Keycloak login
5. User logs in (username/password or Google)
6. Keycloak redirects back with auth code
7. oauth2-proxy exchanges code for tokens, sets cookie
8. User can now access the protected service

## Step 1: Generate Secrets

### 1.1 Keycloak Secrets

| Secret | Description | How to Generate |
|--------|-------------|-----------------|
| `KEYCLOAK_ADMIN_PASSWORD` | Admin console password | Choose a strong password (min 16 chars) |
| `KEYCLOAK_DB_PASSWORD` | PostgreSQL database password | `openssl rand -base64 32` |

**Example:**
```bash
# Generate Keycloak DB password
openssl rand -base64 32
# Output: xK7mN2pQ9rS4tU6vW8xY0zA3bC5dE7fG9hI1jK3lM5n=
```

### 1.2 OAuth2 Proxy Secrets

| Secret | Description | How to Generate |
|--------|-------------|-----------------|
| `OAUTH2_PROXY_COOKIE_SECRET` | Encrypts session cookies | Must be exactly 32 bytes, base64 encoded |
| `OAUTH2_PROXY_CLIENT_ID` | Keycloak client identifier | Always `oauth2-proxy` (hardcoded) |
| `OAUTH2_PROXY_CLIENT_SECRET` | Keycloak client secret | Auto-generated by post-deploy hook |

**Generate cookie secret:**
```bash
# Generate 32-byte cookie secret (URL-safe base64)
openssl rand -base64 32 | tr -- '+/' '-_'
# Output: xK7mN2pQ9rS4tU6vW8xY0zA3bC5dE7fG9hI1jK3lM5n=
```

**Note:** `OAUTH2_PROXY_CLIENT_SECRET` will be generated automatically when Keycloak's post-deploy hook runs. You'll need to retrieve it and add it to GitHub secrets before deploying oauth2-proxy.

### 1.3 Google OAuth Secrets (Optional - for Social Login)

| Secret | Description | How to Obtain |
|--------|-------------|---------------|
| `GOOGLE_CLIENT_ID` | Google OAuth client ID | Google Cloud Console |
| `GOOGLE_CLIENT_SECRET` | Google OAuth client secret | Google Cloud Console |

**How to create Google OAuth credentials:**

1. Go to [Google Cloud Console](https://console.cloud.google.com/)
2. Create a new project or select existing one
3. Navigate to **APIs & Services** → **Credentials**
4. Click **Create Credentials** → **OAuth client ID**
5. Select **Web application**
6. Set name: `Homelab Keycloak`
7. Add Authorized redirect URI: `https://auth.mljr.eu/realms/homelab/broker/google/endpoint`
8. Click **Create**
9. Copy the Client ID and Client Secret

**If you don't want Google login:** Leave these secrets empty. Users will authenticate with username/password only.

### 1.4 SonarQube Secrets

| Secret | Description | How to Generate |
|--------|-------------|-----------------|
| `SONARQUBE_DB_PASSWORD` | PostgreSQL database password | `openssl rand -base64 32` |

**Example:**
```bash
# Generate SonarQube DB password
openssl rand -base64 32
# Output: aB3cD5eF7gH9iJ1kL3mN5oP7qR9sT1uV3wX5yZ7aB9c=
```

## Step 2: Add Secrets to GitHub

1. Go to your repository: https://github.com/MrCodeEU/homelab-automation
2. Navigate to **Settings** → **Secrets and variables** → **Actions**
3. Click **New repository secret** for each:

| Secret Name | Value |
|-------------|-------|
| `KEYCLOAK_ADMIN_PASSWORD` | Your chosen admin password |
| `KEYCLOAK_DB_PASSWORD` | Generated password |
| `OAUTH2_PROXY_COOKIE_SECRET` | Generated 32-byte secret |
| `OAUTH2_PROXY_CLIENT_ID` | `oauth2-proxy` |
| `OAUTH2_PROXY_CLIENT_SECRET` | Leave empty for now (will add after Step 4) |
| `GOOGLE_CLIENT_ID` | From Google Cloud Console (or leave empty) |
| `GOOGLE_CLIENT_SECRET` | From Google Cloud Console (or leave empty) |
| `SONARQUBE_DB_PASSWORD` | Generated password |

## Step 3: Deploy Keycloak

Deploy Keycloak first to generate the oauth2-proxy client:

```bash
cd ansible
ansible-playbook playbooks/site.yml --limit mljr --tags services,caddy -e changed_services=keycloak
```

**What happens:**
1. Keycloak container starts with PostgreSQL
2. Post-deploy hook waits for Keycloak to be ready
3. Hook creates `homelab` realm
4. Hook creates `oauth2-proxy` client with auto-generated secret
5. Hook configures Google identity provider (if credentials provided)

---

## Step 4: Retrieve the Client Secret

After Keycloak deploys, SSH into mljr and retrieve the generated client secret:

```bash
ssh mljr

# Check the hook output for the secret
cat /tmp/keycloak-client-secret.txt
# Output: OAUTH2_PROXY_CLIENT_SECRET=xK7mN2pQ9rS4tU6vW8...

# Or check the deployment logs
docker logs keycloak 2>&1 | grep -A5 "Client created"
```

**Alternative: Get from Keycloak Admin UI**
1. Go to https://auth.mljr.eu/admin
2. Login with `admin` / `<KEYCLOAK_ADMIN_PASSWORD>`
3. Select realm: `homelab`
4. Go to **Clients** → `oauth2-proxy`
5. Go to **Credentials** tab
6. Copy the **Client secret**

**Add to GitHub secrets:**
1. Go to repository Settings → Secrets
2. Update `OAUTH2_PROXY_CLIENT_SECRET` with the retrieved value

---

## Step 5: Deploy OAuth2 Proxy

Now deploy oauth2-proxy:

```bash
cd ansible
ansible-playbook playbooks/site.yml --limit mljr --tags services,caddy -e changed_services=oauth2-proxy
```

**Verify it's working:**
```bash
ssh mljr
curl -I http://localhost:4180/ping
# Should return: HTTP/1.1 200 OK
```

---

## Step 6: Deploy SonarQube

Deploy SonarQube on nuc:

```bash
cd ansible
ansible-playbook playbooks/site.yml --limit nuc --tags services -e changed_services=sonarqube
```

**Note:** The deployment will automatically set `vm.max_map_count=262144` via sysctl.

**Verify SonarQube is running:**
```bash
ssh nuc
curl -s http://localhost:9000/api/system/status | jq '.status'
# Should return: "UP"
```

---

## Step 7: Redeploy Caddy

Redeploy Caddy to update the reverse proxy configuration:

```bash
cd ansible
ansible-playbook playbooks/site.yml --limit mljr --tags caddy
```

### Test Keycloak
1. Go to https://auth.mljr.eu
2. Should show Keycloak welcome page
3. Go to https://auth.mljr.eu/admin
4. Login with `admin` / `<KEYCLOAK_ADMIN_PASSWORD>`

### Test SSO on Protected Service
1. Go to https://logs.mljr.eu (goaccess)
2. Should redirect to Keycloak login
3. Login with Google (if configured) or create a user first

### Test SonarQube
1. Go to https://sonarqube.mljr.eu
2. Should redirect to Keycloak login
3. After login, SonarQube dashboard appears

## Step 9: Create Keycloak Users (If Not Using Google)

If you're not using Google login, create users manually:

1. Go to https://auth.mljr.eu/admin
2. Select realm: `homelab`
3. Go to **Users** → **Add user**
4. Fill in username, email, etc.
5. Click **Create**
6. Go to **Credentials** tab
7. Set a password (uncheck "Temporary")

---

## Step 10: Configure SonarQube (Post-Setup)

After first login to SonarQube:

### Change Admin Password
1. Login as `admin` / `admin` (default)
2. You'll be prompted to change the password

### Create API Token for CI/CD
1. Go to **My Account** (top right) → **Security**
2. Generate a new token named `ci-cd`
3. Copy the token

### Add to External Projects
For each project that should use SonarQube:
1. Add repository secret `SONAR_TOKEN` = the generated token
2. Add repository secret `SONAR_HOST_URL` = `https://sonarqube.mljr.eu`
3. Copy `deployment-template.yml` to `.github/workflows/deploy.yml`

### Configure Quality Gate (Optional)
1. Go to **Quality Gates**
2. Create new or modify "Sonar way"
3. Add conditions:
   - Coverage on New Code < 70% → Fails
   - Duplicated Lines on New Code > 5% → Fails

## Troubleshooting

### Keycloak won't start
```bash
ssh mljr
docker logs keycloak
docker logs keycloak-db
```

Common issues:
- Database password mismatch
- Port 9732 already in use

### OAuth2 Proxy returns 500
```bash
ssh mljr
docker logs oauth2-proxy
```

Common issues:
- Wrong client secret
- Keycloak realm not found
- Cookie secret not 32 bytes

### SonarQube crashes
```bash
ssh nuc
# Check sysctl
sysctl vm.max_map_count
# Should be 262144

docker logs sonarqube
```

Common issues:
- `vm.max_map_count` too low (should be 262144)
- Not enough memory (needs 2GB+)

### Forward auth not working
```bash
ssh mljr
# Test oauth2-proxy directly
curl -I http://localhost:4180/oauth2/auth
# Should return 401 if not authenticated

# Check Caddy logs
tail -f /var/log/caddy/goaccess.log
```

## Services Using Keycloak Auth

After this setup, the following services are protected by Keycloak SSO:

| Service | Domain | Previous Auth |
|---------|--------|---------------|
| GoAccess | logs.mljr.eu | basicauth |
| Fail2ban UI | security.mljr.eu | basicauth |
| SonarQube | sonarqube.mljr.eu | none (new) |

To add more services, update `all.yml`:
```yaml
- name: myservice
  caddy_auth: "keycloak"  # Add this line
```
