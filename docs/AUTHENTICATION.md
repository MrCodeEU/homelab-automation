# GoAccess Authentication Setup

## Overview

The GoAccess web analytics dashboard (`logs.mljr.eu`) uses HTTP Basic Authentication via Caddy to protect access to server logs.

## Current Status

✅ **Infrastructure Complete** - Authentication system fully configured  
⚠️ **Temporarily Disabled** - Auth disabled in `services.yml` until GitHub secrets are verified  
📋 **Ready to Enable** - Follow steps below to activate

## Quick Enable Steps

### 1. Generate Password Hash

Use Caddy to generate a bcrypt hash of your desired password:

```bash
docker run --rm caddy caddy hash-password --plaintext 'your-secure-password'
```

Example output:
```
$2a$14$5w9/qc3yX05cmbTfczhuiuXN8fu6TIopOVgugxBFsbv0e.uTwPD1G
```

⚠️ **CRITICAL**: Copy the ENTIRE hash including the `$` characters!

### 2. Set GitHub Secrets

Add two repository secrets via GitHub web interface or CLI:

```bash
# Via GitHub CLI
gh secret set CADDY_AUTH_USER --body "your_username"
gh secret set CADDY_AUTH_PASSWORD_HASH --body '$2a$14$...full.hash.here...'
```

**Important Notes**:
- Use single quotes around the hash to preserve `$` characters
- Include the FULL hash exactly as generated by Caddy
- Username can be any alphanumeric string (no spaces)

### 3. Enable in services.yml

Edit `configs/services.yml` and change line 60:

```yaml
  # Access Logs (GoAccess) - Real-time web analytics
  - name: goaccess
    enabled: true
    domain: "logs.mljr.eu"
    port: 7890
    host: mljr
    description: "Access Logs"
    icon: "mdi:chart-bar"
    caddy_auth: "basicauth"  # ← UNCOMMENT THIS LINE
```

### 4. Deploy

Push changes and trigger GitHub Actions workflow:

```bash
git add configs/services.yml
git commit -m "feat: enable GoAccess authentication"
git push
```

Then manually trigger the "Deploy VPS" workflow from GitHub Actions tab.

## Testing Authentication

### Verify Secrets are Injected

After deployment, SSH to VPS and check:

```bash
# Should NOT contain placeholders
grep "logs.mljr.eu" -A 5 /etc/caddy/Caddyfile

# Should see: basicauth { username hash }
# Should NOT see: __CADDY_AUTH_USER__ or __CADDY_AUTH_PASSWORD_HASH__
```

### Test Access

```bash
# Without auth - should return 401 Unauthorized
curl -I https://logs.mljr.eu

# With auth - should return 200 OK
curl -I -u 'username:password' https://logs.mljr.eu
```

### Browser Test

1. Visit https://logs.mljr.eu
2. Browser should prompt for username/password
3. Enter credentials set in GitHub secrets
4. Should see GoAccess dashboard

## Troubleshooting

### Issue: Caddy Fails to Start

**Error**: `base64-decoding password: illegal base64 data at input byte X`

**Cause**: Password hash is malformed or incorrectly encoded

**Solution**:
1. Regenerate hash: `docker run --rm caddy caddy hash-password --plaintext 'password'`
2. Verify it starts with `$2a$`, `$2b$`, or `$2y$`
3. Update GitHub secret with FULL hash (60+ characters)
4. Re-deploy

### Issue: Placeholders Still Visible

**Error**: Caddyfile contains `__CADDY_AUTH_USER__` after deployment

**Cause**: `secrets.env` not created or not loaded

**Solution**:
1. Verify GitHub secrets are set: `gh secret list`
2. Check workflow creates secrets.env:
   ```bash
   # In deploy-vps.yml, step "Prepare secrets for injection"
   echo "CADDY_AUTH_USER=${{ secrets.CADDY_AUTH_USER }}" >> secrets.env
   echo "CADDY_AUTH_PASSWORD_HASH=${{ secrets.CADDY_AUTH_PASSWORD_HASH }}" >> secrets.env
   ```
3. Verify secrets.env is copied to VPS:
   ```bash
   tar czf - scripts/ configs/ secrets.env inventory.yml | tailscale ssh ...
   ```

### Issue: 401 Unauthorized with Correct Password

**Cause**: Hash doesn't match password or username is incorrect

**Solution**:
1. Generate new hash for your password
2. Update BOTH secrets (username and hash)
3. Re-deploy
4. Test with exact username from secret

## Technical Details

### Caddyfile Format

The generated Caddyfile uses Caddy's `basicauth` directive:

```caddyfile
logs.mljr.eu {
    basicauth {
        username $2a$14$hash_here
    }
    root * /opt/goaccess/report
    file_server
    reverse_proxy /ws 127.0.0.1:7890
    log {
        output file /opt/caddy/logs/access.log
        format json
    }
}
```

### Secret Injection Process

1. **GitHub Actions** creates `secrets.env`:
   ```bash
   echo "CADDY_AUTH_USER=admin" >> secrets.env
   echo "CADDY_AUTH_PASSWORD_HASH=\$2a\$14\$..." >> secrets.env
   ```

2. **generate-configs.sh** creates Caddyfile with placeholders:
   ```caddyfile
   basicauth {
       __CADDY_AUTH_USER__ __CADDY_AUTH_PASSWORD_HASH__
   }
   ```

3. **inject-caddy-secrets.sh** replaces placeholders using Python:
   ```python
   content.replace('__CADDY_AUTH_USER__', os.environ['CADDY_AUTH_USER'])
   content.replace('__CADDY_AUTH_PASSWORD_HASH__', os.environ['CADDY_AUTH_PASSWORD_HASH'])
   ```

4. **Caddy validates** and starts with the final configuration

### Why Python for Injection?

Bcrypt hashes contain special characters (`$`, `/`, `.`) that break sed/awk:
- `$` triggers variable expansion in bash
- `/` interferes with sed delimiters
- Escaping is error-prone and fragile

Python's string `replace()` handles all characters safely without escaping.

## Security Notes

- ✅ Bcrypt hashes are one-way (cannot be reversed)
- ✅ Secrets stored in GitHub encrypted secrets
- ✅ secrets.env deleted after deployment
- ✅ HTTPS ensures credentials encrypted in transit
- ⚠️ Basic Auth is less secure than OAuth2/OIDC
- 💡 Consider IP allowlisting for additional protection
