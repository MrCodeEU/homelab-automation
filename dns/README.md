# DNS as code (deSEC)

`dnsconfig.js` is the source of truth for the `mljr.eu` zone, hosted at
[deSEC](https://desec.io). Only `mljr.eu` is managed here.

## Workflow

- Edit `dnsconfig.js`, open a PR. CI (`.github/workflows/dns.yml`) runs
  `dnscontrol check` and `dnscontrol preview` with a read-only token.
- On merge to `main`, the `push` job applies the change with a write token.
  It runs in the `dns-production` GitHub environment.

Local preview (token never goes in a file; `creds.json` reads the env var):

```
cd dns && DESEC_TOKEN=... dnscontrol preview
```

## Not managed here

- Apex `NS` records: owned by deSEC, handled by the dnscontrol provider.
- `dkim._domainkey` TXT: generated by Mailcow. After a DKIM rotation, copy
  the new record from the Mailcow admin UI into deSEC by hand. `IGNORE()`
  keeps dnscontrol from deleting it.

## Secrets

GitHub secrets: `DESEC_READ_TOKEN` (no write policy) for PR previews and
`DESEC_WRITE_TOKEN` (write policy scoped to `mljr.eu`, no create/delete/
manage-tokens permission) for the `dns-production` environment. deSEC tokens
cannot rotate themselves: create a new one in the deSEC UI, update the secret,
delete the old token. Set `max_age` when creating a token.

## Known quirk

The provider sets apex NS TTL to deSEC's minimum (900). The live zone had
3600, so the first `push` performs a harmless TTL change.
